# RIVER · 河畔牌局

简约的局域网无限注德州扑克。电脑作为房主运行服务，同一 Wi-Fi 或有线局域网内的朋友可用电脑、平板、手机浏览器加入。支持 2–9 人、房间码、实时同步、断线重连和基础练习对手；全部使用虚拟筹码。

## 如何启动

只有房主电脑需要下载本项目、安装依赖和运行游戏服务。加入者打开房主提供的网页即可；同一真实局域网内的电脑、平板和手机都可加入。

### 第一次安装

房主安装 [Node.js](https://nodejs.org/) **20 或更新版本**（包含 npm），以及用于下载仓库的 [Git](https://git-scm.com/)。在 PowerShell、命令提示符或 macOS / Linux 终端中运行：

```sh
git clone https://github.com/xsky1020/Texas_Poker.git
cd Texas_Poker
npm ci
npm start
```

`npm ci` 根据仓库中的锁文件安装依赖，初次安装需要联网。安装后，再次启动只需进入 `Texas_Poker` 目录并运行 `npm start`。如果下载的是 GitHub 的 ZIP 压缩包，先解压，再在包含 `package.json` 的目录运行相同的 npm 命令。

服务启动后，房主在浏览器打开 [http://localhost:3000](http://localhost:3000)，输入昵称并创建房间。终端会显示本机地址和可用的局域网地址。页面由 Node.js 服务提供，直接双击 `index.html` 无法联机。

### Windows 双击启动

安装 Node.js 后，可直接双击项目根目录中的 **启动牌局.cmd**。脚本会检查 Node.js / npm，依赖缺失时执行 `npm install`，随后启动服务并自动打开浏览器。

保留启动脚本打开的窗口。若 PowerShell 报告 `npm.ps1` 执行策略限制，可使用 `npm.cmd ci`、`npm.cmd start`，或在命令提示符中运行上述命令。

### 修改端口

默认端口为 `3000`。端口被占用或想使用其他端口时，先停止原服务，再选择一个未使用的端口，例如 `3001`。

Windows PowerShell：

```powershell
$env:PORT = '3001'
npm start
```

macOS / Linux：

```sh
PORT=3001 npm start
```

Windows 命令提示符：

```bat
set PORT=3001
npm start
```

本机浏览器地址相应改为 `http://localhost:3001`，朋友的地址和防火墙规则也应使用同一端口。Windows 启动脚本同样读取当前环境中的 `PORT`。

## 局域网多人联机

1. 房主运行服务，在网页输入昵称、创建房间。
2. 所有人连接同一 Wi-Fi 或有线局域网。
3. 房主分享终端显示的 **局域网地址** 和网页中的 **六位游戏房间码**，也可复制页面的邀请链接。
4. 朋友在浏览器访问 `http://<房主局域网IP>:3000`，将占位符替换为房主的真实地址；若房主改过端口，也要替换端口。输入昵称和房间码加入。
5. 至少两名有筹码的玩家就座后，房主点击“开始牌局”。可加入真人，也可添加机器人练习。

`localhost` 和 `127.0.0.1` 指向正在使用浏览器的设备，只用于房主本机访问。朋友应使用房主的局域网 IP。朋友无需克隆仓库或安装 Node.js。

## 用 Radmin VPN 跨局域网联机

朋友位于不同网络时，可将电脑加入同一个 Radmin VPN 虚拟局域网。[Radmin VPN 官方网站](https://www.radmin-vpn.com/cn/)提供 Windows 客户端；以下步骤适用于 Windows 电脑，创建与加入网络的操作可参照[官方帮助](https://www.radmin-vpn.com/cn/help/)。手机浏览器直接加入适用于前面的同一真实局域网方式。

1. 房主和远程朋友分别安装并启动 Radmin VPN。
2. 一人点击“创建网络”，设置 **VPN 网络名称和密码**；朋友点击“加入网络”，输入相同名称和密码。
3. 确认 Radmin VPN 列表中能看到彼此；可右键对方电脑执行 `ping` 检查网络连通。
4. **只有游戏房主运行 `npm start` 或启动牌局.cmd**，并在本机网页创建游戏房间。其余人保持 VPN 在线，用浏览器加入即可。
5. 房主从 Radmin VPN 窗口取得自己的 **虚拟 IP**，将 `http://<房主Radmin虚拟IP>:3000` 和 **六位游戏房间码** 分享给朋友。朋友把占位符替换为该 IP，访问网页后输入昵称和房间码。改过端口时同步使用新端口。

VPN 网络名称和密码用于连接电脑；游戏房间码用于进入这张牌桌，两者分别填写。房主可能有多个网卡，页面自动复制的邀请链接未必选中 Radmin 网卡；异地朋友请使用房主明确提供的 Radmin 虚拟 IP 地址。

## 防火墙与连接排查

游戏网页和实时联机共用一个 **TCP 端口**，默认 `3000`。Windows 房主首次启动时，允许 Node.js 在所用的网络配置文件中接收入站连接；家庭局域网通常选择“专用网络”。

若之前拒绝过弹窗，可打开 **Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 更改设置**，勾选 **Node.js JavaScript Runtime** 及实际网络类型。找不到时选择“允许其他应用”，添加 `node.exe`；可在命令提示符运行 `where node` 查询其安装路径。操作参考[微软允许应用通过防火墙说明](https://support.microsoft.com/en-us/windows/security/firewall/risks-of-allowing-apps-through-windows-firewall)。

也可为游戏创建端口规则：进入 **防火墙和网络保护 → 高级设置 → 入站规则 → 新建规则 → 端口**，选择 **TCP**，将“特定本地端口”设为 `3000`（或实际端口），选择“允许连接”，勾选当前网络配置文件，再为规则命名。可在规则属性的“作用域”中限制朋友的 IP 地址。流程参考[微软入站端口规则说明](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure)。

Radmin 虚拟网卡若被 Windows 识别为“公用网络”，只勾选“专用网络”的规则不会匹配；此时应让端口规则匹配该配置文件，并在作用域中限定朋友的 Radmin 虚拟 IP。macOS / Linux 若启用了防火墙，也应允许房主服务实际使用的 TCP 端口。保持防火墙启用，仅放行所需程序或端口。

连接失败时，按以下顺序检查：

- 房主的服务窗口仍在运行，本机能打开 `http://localhost:<端口>`。
- 朋友使用的是房主 IP、正确端口和当前房间码；Radmin 联机应使用虚拟 IP。
- 真实局域网没有访客网络 / AP 隔离；Radmin 联机时双方在同一 VPN 网络且保持在线。
- 房主的 Node.js / TCP 端口规则适用于当前网络类型，第三方防火墙也已放行。
- 同一浏览器刷新后可尝试恢复座位；若服务已经重启，需要重新创建或加入房间。

游戏进行时，房主需保持电脑开机、服务窗口运行；Radmin 联机还需保持 VPN 在线。按 `Ctrl+C` 或关闭服务窗口会结束服务。**房间、筹码和牌局状态保存在内存中，服务重启后全部清空。**

## 自定义设置

房主在创建房间时及两手之间调整设置；手牌进行中禁止改规则。除房间名和开关外，数值均为整数。

| 设置 | 默认值 | 单位与行为 |
| --- | ---: | --- |
| 小盲 / 大盲 | 50 / 100 | 筹码；小盲不大于大盲，大盲不超过最大买入 |
| 前注 | 0 | 筹码；每手所有参与玩家先投入，0 为关闭 |
| 初始筹码 | 10000 | 新加入玩家的筹码，须在最小和最大买入之间 |
| 最小 / 最大买入 | 2000 / 20000 | 补充筹码的单次金额范围；补充后持有筹码也不能超过最大买入 |
| 行动时间 | 30 | 秒，1–300；超时且可过牌时自动过牌，否则自动弃牌 |
| 人数上限 | 6 | 人，2–9，含练习对手 |
| 加盲间隔 | 0 | 分钟，0–1440；0 为关闭；按已开始的牌局计时，在下一手更新盲注 |
| 加盲倍数 | 2 | 倍，2–10；每到一个盲注等级，小盲和大盲按倍数增长 |
| 牌局时长 | 0 | 分钟，0–1440；0 为不限时；从第一手开始计算，到时打完当前手后停止开新手 |
| 手牌间隔 | 5 | 秒，0–300；用于自动发下一手 |
| 自动发牌 | 关闭 | 开启后，当前手结束且至少两名有筹码玩家在线时，按间隔开新手 |

筹码设置的最大值分别为：盲注及前注 100000000，初始筹码及买入 1000000000。修改初始筹码不会重置已就座玩家的筹码。累计买入会记录在玩家信息中。

## 牌桌操作

- **弃牌**：放弃当前手。
- **过牌 / 跟注**：未欠注时过牌；否则跟齐本轮下注，筹码不足时投入剩余全部筹码。
- **加注到**：输入的是本轮累计下注总额。例如已投入 50，“加注到 300”会再投入 250。
- **全下**：投入剩余全部筹码；多方全下按各人的投入结算主池与边池。
- **买入**：未参与当前手、已弃牌或两手之间时可补充虚拟筹码，遵守房间买入范围和持有筹码上限。
- **下一手**：房主手动开始下一手，或开启自动发牌。

庄家按钮与盲注位置每手轮转。采用标准五张最佳牌型比较、平分底池和边池结算；弃牌赢得底池时不公开胜者底牌，正常摊牌公开仍参与的玩家底牌。行动期间服务器只向每位玩家发送其自己的真实底牌。

同一浏览器刷新后会尝试恢复原座位；保留浏览器站点存储可保留重连凭证。断线后座位和筹码暂时保留，轮到离线玩家时会缩短等待时间。主动离开会使该座位的重连凭证失效；若手牌仍在进行，离开的玩家会在本手结束后移除。房主断线或离开时，房主权限交给其他在线真人玩家。

练习对手用于测试和练手，采用简单的随机策略。游戏没有账号、充值或现金兑换功能。

## 验证与开发

```powershell
npm test
```

规则测试检查牌型、行动顺序、盲注、全下与底池等边界，并通过随机完整对局检查筹码守恒；联机测试使用独立 WebSocket 客户端，覆盖房间设置、权限、底牌隔离、整手同步、筹码守恒、重连、房间隔离、房主迁移、超时行动、自动发牌和买入约束。

浏览器测试在 **Windows 使用本机安装的 Google Chrome**。安装 Chrome 后运行：

```sh
npm run test:browser
```

**macOS / Linux 使用 Playwright Chromium**，先安装测试浏览器，再运行测试：

```sh
npx playwright install chromium
npm run test:browser
```

Linux 若提示缺少系统依赖，可使用 `npx playwright install --with-deps chromium` 安装浏览器及所需依赖。正常启动游戏只需要 Node.js / npm；上述测试浏览器用于开发验证。

服务端入口为 `server.js`，牌局规则为 `poker-engine.js`；前端由 `index.html`、`styles.css` 和 `game.js` 组成，无需构建。
